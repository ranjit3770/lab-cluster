# Cluster via Ansible

Ansible playbooks for setting up and maintaining the Slurm cluster.

The repository is designed around one operator entrypoint:

```bash
ANSIBLE_HOST_KEY_CHECKING=False ansible-playbook -i hosts.ini cluster_manage.yml --ask-vault-pass
```

When prompted, choose:

- `setup` for a fresh or full Slurm cluster setup.
- `append` to add one new worker node to an existing working cluster.

## Important Files

- `hosts.ini`
  Main inventory. Linux Slurm hosts are under `[head_nodes]` and `[cluster_nodes]`.

- `cluster_manage.yml`
  Recommended entrypoint. Asks whether to run full setup or append mode.

- `step4_main.yml`
  Full Slurm deployment sequence.

- `finally/append_slurm_node.yml`
  Appends one new worker node.

- `finally/repair_unknown_slurm_nodes.yml`
  Repairs Slurm nodes that are `UNKNOWN`, `INVALID`, `DOWN`, or `DRAIN`, and verifies worker `slurmd`.

- `cmds.txt`
  Command reference.

## Inventory Pattern

Linux Slurm nodes use underscore inventory names:

```ini
[head_nodes]
head_node ansible_host=172.17.181.171

[cluster_nodes]
worker_node1  ansible_host=172.17.181.143
worker_node2  ansible_host=172.17.181.144
```

Slurm node names are generated by replacing underscores with hyphens:

```text
head_node     -> head-node
worker_node1  -> worker-node1
```

Keep this pattern consistent when adding new workers.

## Common Commands

Run the guided setup/append entrypoint:

```bash
ANSIBLE_HOST_KEY_CHECKING=False ansible-playbook -i hosts.ini cluster_manage.yml --ask-vault-pass
```

Run full Slurm setup directly:

```bash
ANSIBLE_HOST_KEY_CHECKING=False ansible-playbook -i hosts.ini step4_main.yml --ask-vault-pass
```

Append one worker directly:

```bash
ANSIBLE_HOST_KEY_CHECKING=False ansible-playbook -i hosts.ini finally/append_slurm_node.yml --ask-vault-pass
```

Repair unhealthy Slurm nodes:

```bash
ANSIBLE_HOST_KEY_CHECKING=False ansible-playbook -i hosts.ini finally/repair_unknown_slurm_nodes.yml --ask-vault-pass
```

Syntax-check the main entrypoint without changing cluster machines:

```bash
ANSIBLE_LOCAL_TEMP=/tmp/ansible-local ansible-playbook -i hosts.ini cluster_manage.yml --syntax-check
```

## Operating Rules

- Use playbooks for cluster changes.
- Do not manually run Slurm repair commands unless there is an emergency.
- Use `append` mode for one new worker.
- Use `setup` mode only for fresh setup or full rebuild.
- Keep `hosts.ini` current and backed up with the cluster configuration.
- Review playbook output at the end for final `sinfo` and `slurmd` status.

## Full Setup Flow

The full setup path is managed by `step4_main.yml`. It imports the Slurm tasks in order:

1. Cleanup existing worker Slurm/Munge install.
2. Install dependencies.
3. Prepare Munge permissions.
4. Sync Munge key from the head node.
5. Verify Munge.
6. Build/install Slurm.
7. Create Slurm users, directories, and runtime paths.
8. Generate Slurm configuration dynamically from inventory and node hardware.
9. Configure SlurmDBD.
10. Deploy systemd services.
11. Start Slurm services.
12. Apply final fixes and online verification.
13. Repair unhealthy nodes and verify worker `slurmd`.

See [Fresh Slurm Cluster Setup](FRESH-SLURM-CLUSTER-SETUP.md) for the full operator procedure.

## Append Flow

The append path is managed by `finally/append_slurm_node.yml`. It prepares only the requested new worker, regenerates controller configuration from inventory, starts `slurmd` on the new worker, resumes it in Slurm, and verifies all workers.

See [Append a New Slurm Worker Node](APPEND-NEW-NODE.md) for the detailed procedure.
